    01 · 开始之前

    把任何一台机器变成离线 AI 终端

    Termux AI Harness 是两件事合在一起：一个跑在本机的 llama.cpp 推理服务，加上一个会说人话、也能替你敲命令的终端客户端。

    它做了什么

    • 全链路走 127.0.0.1，不联网也能用，不要 API Key，没有额度限制。
    • 自动找 llama-server、自动扫 GGUF 模型、一键下载、启动后直接进聊天。
    • 聊天里带网址，它会真的打开网页取正文并截图，再把内容交给模型。
    • 回答分成 TEXT: 和 CMD:：说话归说话，命令先打印、按 y 才执行。
    • 桌面端覆盖 Windows / macOS（Intel + Apple 芯片）/ Linux，Android 走 Termux。

    它不做什么

    它不是云服务，不替你保存对话，也不保证命令安全——危险命令有黑名单，但那是模式匹配，不是沙箱。这台机器上真正执行命令的人还是你。

    许可：MIT。模型许可见 THIRD-PARTY-NOTICES.md，Qwen 是 Apache-2.0，Llama 3.2 是社区许可。
    02 · 开始之前

    你需要一台什么样的机器

    系统

    平台方式依赖
    AndroidTermux（F-Droid 版）curl、jq，脚本自动装
    Linuxbash 脚本curl、jq
    macOSbash 脚本curl、jq（brew 装）
    WindowsPowerShell 脚本无，系统自带

    内存与机型

    • 4GB 内存级：跑 0.5B / 1.1B，-c 512。
    • 6~8GB：跑 1.5B / Llama-3.2-1B，-c 1024。
    • 8GB 以上：跑 3B，-c 2048，这是推荐起点。
    留一半内存给系统。Android 的内存回收很凶，llama-server 常驻超过可用内存的一半，很容易被系统直接杀掉，表现为“聊两句就断”。

    暂不支持

    纯血鸿蒙（HarmonyOS NEXT）没有可用的 POSIX shell，装不了 llama.cpp；iOS / iPadOS 沙箱不允许 fork/exec 外部二进制。这两项不是待办，是环境本身不满足。

    03 · 安装

    拿到安装包，并确认它没坏

    官网首页的下载区会实时从 GitHub Releases 拉版本号和文件名，点平台名直接开始下载，默认走国内加速节点，文件与 GitHub 原包逐字节一致。

    从命令行取

    # 以 v1.5.0 为例，换成 latest 可自动取最新
curl -L -O https://github.com/Huangqia123/termux-ai-harness/releases/download/v1.5.0/TermuxAIHarness-1.5.0-android.apk
curl -L -O https://github.com/Huangqia123/termux-ai-harness/releases/download/v1.5.0/SHA256SUMS-1.5.0.txt

    校验

    sha256sum -c SHA256SUMS-1.5.0.txt

    看到每行 OK 就说明文件完整。加速节点偶尔抽风时不一定是文件坏，也可以点每张下载卡下面的「GitHub 原链」重下一次。

    如果你是直接克隆仓库用脚本（不装 GUI），这一步可以跳过——脚本就在仓库 bin/ 和 install.sh 里。
    04 · 安装

    在 Termux 里装好两个命令

    先更新源

    pkg update && pkg upgrade -y
pkg install -y git curl jq

    拉仓库并安装

    git clone https://github.com/Huangqia123/termux-ai-harness.git
cd termux-ai-harness
bash install.sh

    脚本会自动检测平台，在 Termux 上装到 $PREFIX/bin，依赖缺失时用 pkg 补。装完你会得到两个命令：

    • termuxai —— 只会聊天的客户端，不会执行任何命令。
    • termuxai-harness —— 带命令执行能力的 agent，危险命令会被拦。

    Android 还有一种用法

    直接装 TermuxAIHarness-*.apk，那是一个前端外壳，不内置模型，仍然是连你 Termux 里跑着的引擎。所以 APK 和 Termux 两样都得有。

    05 · 安装

    三步，五分钟

    顺序别反：先起模型服务，再启动客户端。客户端一连不上就会报“connection refused”，那不是装错了，是引擎还没起来。

    第一步：起 llama-server

    llama-server -m qwen2.5-1.5b-instruct-q4_k_m.gguf -c 1024 --port 8080 -t 6

    看到 HTTP server listening 之类的行就算起来了。这个终端不要关，它是引擎。

    第二步：另开一个终端

    termuxai-harness

    第三步：说话

    直接输入自然语言。想让它干活就说得具体一点：“看看当前目录里最大的文件”，它会把命令打印出来，等你按 y。

    端口 8080 被占用时，桌面端会自动退到 8081–8091；手动起服务时自己挑一个空端口，再把 TERMUX_AI_URL 指过去。
    06 · 模型

    六个模型，按内存分三档

    全部 Q4_K_M 量化，配默认参数开箱即用。每档都是一个中文、一个英文。

    档位适用设备中文英文建议 -c
    低配4GB 级Qwen2.5-0.5BTinyLlama-1.1B512
    中配6~8GB 级Qwen2.5-1.5BLlama-3.2-1B1024
    高配8GB 以上Qwen2.5-3BLlama-3.2-3B2048

    为什么中文用 Qwen、英文用 Llama

    Qwen2.5 的中文语料占比高，指令跟随和中文输出稳定性明显好于同尺寸英文模型；英文侧 Llama-3.2 的对话质量和理解更好。

    3B 的真正价值不在速度

    荣耀平板 X9 上实测：3B 常规 9–15 token/s，短提示命中缓存最高 46 token/s；同机换 1.5B 是 9–14 token/s，差得不多。拉开差距的是它守得住 CMD: / TEXT: 协议——1.5B 经常忘记前缀，harness 就会误判。

    07 · 模型

    不想用图形界面，就自己拉

    仓库自带 download-models.sh，默认走 hf-mirror.com，国内比直连 huggingface.co 稳。

    chmod +x download-models.sh
./download-models.sh low-cn     # 低配中文
./download-models.sh mid-cn     # 中配中文
./download-models.sh high-cn    # 高配中文
./download-models.sh low-en mid-en high-en

    放哪儿

    放进仓库的 models/ 目录，或者任何你顺手的位置，起服务时用绝对路径指过去就行。几百 MB 到几 GB 的二进制不进 git，.gitignore 里已经排除了。

    下完先看一眼大小

    模型体积常驻内存估算
    0.5B约 491MB0.4~0.6GB
    1.5B约 1.12GB1.2~1.5GB
    3B约 1.8GB2.2~2.6GB
    Q4_K_M 大致是每 10 亿参数 0.6~0.7GB 常驻，再加 KV cache。别只看模型文件大小，要留出上下文占的那部分。
    08 · 模型

    llama-server 这几个参数决定手感

    -m

    模型文件路径。只有一个模型时可以省略，harness 会自己扫。

    -c

    上下文长度。它和速度、内存是三角关系：-c 越大越吃内存、越慢。低配 512，中配 1024，高配 2048 就够，别盲目上 4096。

    -t

    线程数。按设备大核数量设，超了反而变慢，因为小核拖后腿。-t 4 在多数中端机上就是甜点。

    --port

    默认 8080。改端口后记得同步 TERMUX_AI_URL。

    显存 / 内存不够的先降哪个

    1. 先降 -c，它对内存的影响最直接。
    2. 再换小一档模型。
    3. 最后才动线程数——线程降了是实打实变慢。
    出现 failed to allocate 或进程被系统杀掉，基本都是这一条路径走下来的问题，不是装错了。
    09 · 使用

    它怎么区分“说话”和“动手”

    模型的回复必须以两个前缀之一开头：

    • TEXT: —— 当回答打印，永远不进 shell。
    • CMD: —— 先展示命令，等你按 y 才执行。

    模型忘了写前缀时，客户端会按“形状”兜底判断：看着像命令的那一行，宁可当话处理，也不会把一句话当命令跑掉。

    确认流程长这样

    [CMD] du -sh * | sort -h | tail -5
run? [y/N] _

    按 n 或直接回车都等于取消。执行完的输出会回灌给模型，让它接着往下说。

    两个命令的区别

    termuxai 只会聊天，没有 CMD 能力；termuxai-harness 才有执行链。想纯聊天、怕手滑，就用前者。

    10 · 使用

    人在回路，但别把它当保险箱

    每条命令都会先打印，默认要按 y 确认。递归删除、磁盘格式化、关机重启、fork bomb 这类直接拒绝，连确认机会都不给。

    黑名单大致覆盖

    • rm -rf / 一类递归删除、通配删除
    • mkfs、dd 覆写磁盘、format
    • shutdown、reboot、halt
    • fork bomb 形状的递归调用
    这是模式匹配，不是沙箱。换个写法的破坏性命令仍可能绕过去。它挡的是手滑和模型犯傻，不是恶意构造。执行前自己扫一眼那行命令。

    不想每次按 y？

    TERMUX_AI_AUTO_RETRY=1 会跳过确认。别在你不看着屏幕的时候开这个。

    11 · 使用

    命令报错了，它会自己改

    命令失败时，客户端把命令原文和输出一起交回模型，让它给出修正版本，最多重试 TERMUX_AI_MAX_RETRY 次（默认 2）。

    export TERMUX_AI_MAX_RETRY=1   # 保守：只给一次改的机会

    为什么要有上限

    没有上限的话，模型会在同一个错误上反复绕圈，既费时间又费电。两次已经是“明显是我写错了”的量级，再多基本说明信息不够，该你自己补。

    重试仍然逐条确认，不会因为“在重试”就静默执行。
    12 · 使用

    所有可调项都在这里

    变量默认说明
    TERMUX_AI_URLhttp://127.0.0.1:8080/v1/chat/completions推理接口地址
    TERMUX_AI_MODEL空模型名，OpenAI 兼容后端用得上
    TERMUX_AI_TEMPERATURE0.2 / 0.1采样温度，越高越发散
    TERMUX_AI_MAX_TOKENS512 / 256单次输出上限
    TERMUX_AI_TIMEOUT120超时秒数
    TERMUX_AI_AUTO_RETRY0仅 harness，1 跳过确认
    TERMUX_AI_MAX_RETRY2仅 harness，失败重试上限

    怎么设

    # bash / Termux
export TERMUX_AI_URL=http://127.0.0.1:8080/v1/chat/completions

# PowerShell
$env:TERMUX_AI_URL = "http://127.0.0.1:8080/v1/chat/completions"

    想长期生效，bash 写进 ~/.bashrc 或 ~/.zshrc；PowerShell 用 [Environment]::SetEnvironmentVariable 写用户级变量。

    13 · 进阶

    聊天里贴网址，它会真的打开

    桌面端用一个离屏窗口加载目标网址，执行脚本取 document.body.innerText，再用 capturePage() 截首屏存到 userData/shots/。

    • 拿到的是 JS 渲染后的正文，不是 curl 那层原始 HTML。
    • 正文按上下文预算截断，超出的部分丢掉——所以问得越具体，答得越准。
    • 截图会随对话一起给模型，配合视觉模型能看版面。
    整条链路不依赖外部 API，网页内容也不会被上传到任何地方。

    什么时候会翻车

    需要登录的页面、纯 Canvas 渲染的页面、反爬很凶的站点，取到的正文可能只有一句“请开启 JavaScript”。这时候换用截图理解，或者自己把关键段落贴进来。

    14 · 进阶

    给它看图

    点输入框旁边的「图片」按钮，或者直接 Ctrl+V 粘贴截图，图片会和文字一起交给模型。

    用对模型

    普通 Qwen2.5 文本模型看不了图，需要换成视觉模型（Qwen2.5-VL 系列）。模型目录里可以放多个，起服务时指哪个用哪个。

    能做什么

    • 描述画面、识别界面元素、读表格截图
    • 看报错截图并指出问题行
    • 配合网页截图理解整页排版
    图片走 data: 内联，占上下文很快。一张长截图可能吃掉几百 token，问的时候别一次贴十张。
    15 · 桌面端

    Windows：一套 PowerShell 实现

    不是 bash 套壳。用 PowerShell 原生能力替代 curl 和 jq，不需要 Git Bash 或 WSL。

    确认版本

    $PSVersionTable.PSVersion

    5.1 是 Win10/11 自带，够用；7.x 更好，去 aka.ms/powershell 装。

    安装

    powershell -ExecutionPolicy Bypass -File windows\install.ps1

    脚本做三件事：把两个 .ps1 复制到 %LOCALAPPDATA%\TermuxAI\bin；生成同名 .cmd 启动器（内部自带 Bypass）；把这个目录加到用户级 PATH，不碰系统 PATH，不要管理员权限。

    跑

    llama-server.exe -m model.gguf -c 1024 --port 8080
termuxai-harness
    GUI 版是 zip，解压双击 exe。没有签名，SmartScreen 会拦一次：更多信息 → 仍要运行。

    17 · 桌面端

    不装包，直接在浏览器里用

    官网的「网页版」入口打开的是同一套界面，跑在浏览器里。但引擎仍然在你本机——网页只通过 127.0.0.1 连你 Termux 或命令行里起的 llama-server。

    用法

    1. 本机先起引擎：llama-server -m model.gguf -c 1024 --port 8080
    2. 浏览器打开官网 web/ 页面。
    3. 地址栏填 http://127.0.0.1:8080，连通后即可对话。
    浏览器有同源与跨域限制。如果你的引擎在别的设备（比如手机跑引擎、电脑开网页），要么走局域网地址并在服务端放行跨域，要么直接在跑引擎的那台机器上开网页。
    18 · 排错

    这几类报错，八成是同一批原因

    connection refused

    引擎没起，或端口不对。先 curl http://127.0.0.1:8080/v1/models 看看有没有响应。

    404 / 路径不存在

    TERMUX_AI_URL 少了 /v1/chat/completions，或者后端不是 OpenAI 兼容接口。

    failed to allocate / 进程被杀

    内存不够。降 -c、换小模型、关掉后台应用。Android 上尤其容易发生在切后台之后。

    Permission denied

    装到 /usr/local/bin 却没权限，改用 bash install.sh 的默认用户安装；或者脚本没执行位，chmod +x。

    命令没反应，只回一句话

    模型没守 CMD: 前缀。换大一点的模型（3B 明显更稳），或在提示里强调“需要执行命令时必须以 CMD: 开头”。

    聊两句就断

    软超时。本地推理慢，TERMUX_AI_TIMEOUT 调到 180 试试；也可能是内存被回收。

    19 · 进阶

    让它跑得久一点

    线程别贪

    -t 按大核数设。小核参与计算会拖慢整体，看着“占满 8 核”其实更慢。

    上下文别贪

    -c 2048 够日常；长文档总结再上 4096。每加一档，内存和首字延迟都往上走。

    Android 保活

    • Termux 里执行 termux-wake-lock，避免息屏被挂起。
    • 系统设置里给 Termux 关掉电池优化。
    • 别在推理时同时开一堆应用——内存回收第一个杀的就是常驻进程。

    温度

    手机长时间满载会降频，表现为“越聊越慢”。这不是软件问题，散热背夹比调参数有用。

    实测参考（荣耀平板 X9，3B，-c 2048 -t 4）：常规 9–15 token/s，短提示命中 slot 缓存最高 46 token/s。
